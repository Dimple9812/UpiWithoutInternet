# Deploy the MeshPay website for free

This puts the simulator online at a public URL like `https://meshpay-xxxx.onrender.com`,
for ₹0 a month and with no card needed.

| Piece | Service | Free plan |
|---|---|---|
| Website (Spring Boot) | [Render](https://render.com) | Free web service: 512 MB RAM, 750 hours a month, sleeps after 15 min idle |
| Database (PostgreSQL) | [Neon](https://neon.com) | Free forever: 1 GB storage, sleeps when idle |
| Redis | Not needed | The `cloud` profile uses the in-memory idempotency store (fine for one instance) |

**The trade-off:** after 15 minutes without visitors, the site goes to sleep. The next
visitor waits about a minute while it wakes up. Open the site a minute before you
demo it to someone.

Render also has a free PostgreSQL, but it is deleted after 30 days. Neon's free plan
doesn't expire, so use Neon.

## 1. Create the database on Neon (about 3 minutes)

1. Sign up at [neon.com](https://neon.com) (GitHub sign-in works) and create a project,
   e.g. `meshpay`. Pick the region closest to you (for India: Singapore).
2. On the project dashboard, click **Connect** and copy the connection details. You
   need three values:
   - **Host**, e.g. `ep-cool-name-123456.ap-southeast-1.aws.neon.tech`
   - **User**, e.g. `neondb_owner`
   - **Password**
3. Write your JDBC URL like this, replacing the host and the database name (`neondb`
   unless you changed it):

   ```
   jdbc:postgresql://ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

   The app creates its own tables on first start (Flyway), so there is nothing else to
   set up.

## 2. Deploy the website on Render (about 5 minutes)

1. Sign up at [render.com](https://render.com) with GitHub and allow it to access the
   `UpiWithoutInternet` repository.
2. Click **New → Blueprint** and choose the repository. Render reads `render.yaml`
   from the repo.
3. Render asks for three values. Paste them from step 1:

   | Key | Value |
   |---|---|
   | `MESHPAY_DB_URL` | the JDBC URL you wrote above |
   | `MESHPAY_DB_USER` | Neon user |
   | `MESHPAY_DB_PASSWORD` | Neon password |

   `MESHPAY_MASTER_KEY` and `MESHPAY_DEMO_BRIDGE_TOKEN` are generated by Render
   automatically. Don't change the master key later: it unlocks the server's stored
   keys.
4. Click **Apply**. The first build takes a few minutes (Maven downloads dependencies,
   then the Docker image is built). When the service shows **Live**, open its URL.

Every push to the branch Render watches redeploys the site automatically.

## 3. Check it works

- `https://<your-app>.onrender.com/actuator/health` should show `{"status":"UP"}`.
- On the home page, press **Pay offline**, then **Run**. Within a few seconds a phone
  carries the payment into the 4G zone and it settles.

## If something goes wrong

| What you see | What to do |
|---|---|
| Build fails | Open the Render **Logs** tab. The error is usually near the end of the Maven output. |
| `Connection refused` or `password authentication failed` | Re-check the three database values. The URL must start with `jdbc:postgresql://` and end with `?sslmode=require`. |
| `cannot unwrap key` | The master key changed after the first start. Put the original value back, or create a fresh Neon database. |
| Page takes about a minute to load | The free instance was asleep. This is normal. |

## Notes

- Everyone who opens the site shares one simulated mesh. **Reset mesh** resets it
  for all visitors.
- The demo uses fake accounts and fake money (PIN 1234). It is not connected to any
  bank or to UPI.
- To run several instances later, switch back to Redis: remove `cloud` from
  `SPRING_PROFILES_ACTIVE` and set `MESHPAY_REDIS_HOST` and `MESHPAY_REDIS_PORT`.
